## Feature matrix

| Capability | Logixlysia | [evlog](https://evlog.dev) | [@bogeychan/elysia-logger](https://github.com/bogeychan/elysia-logger) |
| --- | --- | --- | --- |
| Elysia plugin | Yes | Yes (`evlog/elysia`) | Yes |
| Pino-backed | Own request logger; pino on `store.pino` | Optional drains | Yes |
| Request context accumulation | `mergeContext`, `useLogger()` | `log.set()`, `useLogger()` | Manual |
| Single access log per request | Auto | `log.emit()` | Auto |
| File rotation | Yes | Via drains | Limited |
| `autoRedact` PII | Yes | Varies | Manual |
| WebSocket lifecycle logs | `wrapWs` | Manual | Manual |
| OTel trace correlation | `logixlysia/otel` | Built-in integrations | Manual |
| AI usage on access log | `logixlysia/ai` | `evlog/ai` | Manual |
| Presets (`dev` / `prod`) | Yes | N/A | N/A |
| Built-in destinations | 9 adapters: Axiom, Better Stack, ClickHouse, Datadog, HyperDX, Loki, OTLP, PostHog, Sentry (`logixlysia/<name>`) | Managed drains | Manual |
| Head + tail sampling | Yes | Yes | No |
| Enrichers | Built-in (`logixlysia/enrichers`) + custom | Yes | Manual |
| Structured errors (`why` / `fix`) | `HttpError` | `createError` | No |
| Neural PII redaction | `logixlysia/desertant` | Not built in | Not built in |

## When to choose Logixlysia

- You want automatic access logs with Elysia-native `store.logger` ergonomics, and a pino instance on `store.pino` for your own logs.
- You need **file logging and rotation** without wiring a separate drain.
- You prefer **incremental context** (`mergeContext`) plus automatic access logs instead of migrating to a wide-event-only API.

## When to consider evlog

- You need a logger that spans more than Elysia: evlog also covers Nuxt, Nitro, Next.js, and Hono.
- You want evlog's CLI and observability scoring built in.
- You want evlog's error catalog and client/browser logging.
- You rely heavily on **`evlog/ai`** and **`evlog` auth** integrations out of the box.

## Benchmarks

Run the monorepo benchmark package:

```bash
bun run bench
```

The benchmark package has a suite that times creating each logger, three plain-log suites in which six loggers write a string, an object and a deeply nested object into the same no-op sink, and four request suites: a **plugin request path** run that times each Elysia logging plugin from the request until its log line reaches the sink, a **no-logger reference** (plain Elysia with no plugin, the floor the others sit on), a **structured sink** run (logixlysia only, the `prod` and `json` presets writing to a no-op transport), and a **file sink** run (logixlysia only; the file write is not awaited, so it is not comparable with the others). Results vary by machine — use them for regression tracking, not absolute rankings.
