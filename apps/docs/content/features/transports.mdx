title: Custom Transports

用自定义 transport 把日志发到外部服务。transport 跟内置的 console / file 日志并行,统一从 emit 管道调用。

## 输出行为

Logixlysia 支持三种输出目标:

1. **Console 日志** —— 内置控制台输出
2. **File 日志** —— 通过 file sink 输出
3. **Transport 日志** —— 自定义外部服务

### 输出控制

- **默认:** console + file(如果设置了 `logFilePath`)+ transports
- **`disableInternalLogger: true`:** 只关 console
- **`disableFileLogging: true`:** 只关 file
- **`useTransportsOnly: true`:** 同时关 console 和 file,只走 transport

## 基本 transport

```ts
import type { Transport } from '@pori15/logixlysia'

const consoleTransport: Transport = {
  log: (level, message, meta) => {
    console.log(`[${level}] ${message}`, meta)
  },
}

app.use(
  logixlysia({
    config: {
      transports: [consoleTransport],
    },
  })
)
```

签名是 `(level: LogLevel, message: string, meta?: Record<string, unknown>) => void | Promise<void>`。异步 transport 返回 promise,同步 transport 返回 `void`。

## 外部服务

### Elasticsearch

```ts
const elasticsearchTransport: Transport = {
  log: async (level, message, meta) => {
    await fetch('http://elasticsearch:9200/logs/_doc', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        level,
        message,
        ...meta,
        timestamp: new Date().toISOString(),
      }),
    })
  },
}
```

### MongoDB

```ts
const mongodbTransport: Transport = {
  log: async (level, message, meta) => {
    await db.collection('logs').insertOne({
      level,
      message,
      ...meta,
      timestamp: new Date(),
    })
  },
}
```

### Slack

```ts
const slackTransport: Transport = {
  log: async (level, message, meta) => {
    if (level !== 'ERROR') return
    const webhook = process.env.SLACK_WEBHOOK_URL
    if (!webhook) return

    await fetch(webhook, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        text: `[${level}] ${message}\n\`\`\`${JSON.stringify(meta, null, 2)}\`\`\``,
      }),
    })
  },
}
```

## 多个 transport

```ts
app.use(
  logixlysia({
    config: {
      transports: [elasticsearchTransport, slackTransport],
    },
  })
)
```

数组里的 transport 顺序调用,各自独立 —— Elasticsearch 慢不会阻塞 Slack。

## 只用 transport

```ts
app.use(
  logixlysia({
    config: {
      useTransportsOnly: true,
      transports: [elasticsearchTransport, slackTransport],
    },
  })
)
```

## 错误处理 & 节流

transport 抛出的同步异常和异步 reject 都会被捕获并打印到 `console.error`。为了防止坏掉的 transport 每个请求都刷一屏 stderr,同一 transport 的同一错误在 `transportThrottleMs`(默认 5s)窗口内合并为一条 `console.error`。

```ts
logixlysia({
  config: {
    transportThrottleMs: 10_000, // 10s 窗口
  },
})
```

这是生产环境的安全阀。你仍然应该在 transport 内部自己处理错误,接到自己的监控系统。

## 最佳实践

- **在 transport 内部处理错误** —— logixlysia 捕获了 throw,但只打印到 `console.error`,不会送回你的目标。
- **异步用 `Promise<void>`** —— logixlysia 会 await 异步 transport 的返回值。
- **避免在 `meta` 里写 secret / PII** —— 脱敏会处理 message 和 key 字段,但 transport 拿到的就是管道给的原始数据。
- **生产只接外部聚合器时,设 `useTransportsOnly: true`**
- **按重要性排 transport 顺序** —— 告警放最前,批写放最后

## Transport 接口

```ts
export interface Transport {
  log: (
    level: LogLevel,
    message: string,
    meta?: Record<string, unknown>
  ) => void | Promise<void>
}

export type LogLevel = 'DEBUG' | 'INFO' | 'WARNING' | 'ERROR'
```

## 组合器(Composers)

Transport 接口只有一个 `log` 方法,所以**(Transport) => Transport** 的纯函数可以任意堆叠,跟 pino multi-stream 一样。logixlysia 给了 5 个常用组合器,从 `@pori15/logixlysia` 直接 import:

| 组合器 | 用途 |
| --- | --- |
| `tee([t1, t2, ...])` | 多路 fan-out,任一失败不短路 |
| `sample(rate, t)` | 概率采样(0-1) |
| `filter(predicate, t)` | 谓词过滤 |
| `tap(fn, t)` | 旁路(metrics / 计数),不影响主链路 |
| `batch(size, ms, t)` | 缓冲 `size` 条或 `ms` 毫秒,合成一条发 |

### tee —— 多路 fan-out

把一条 log 同时发到多个 transport。任一分支 throw 或 reject 都不会短路其它分支(用 `Promise.allSettled` 兜底)。

```ts
import logixlysia, { tee } from '@pori15/logixlysia'

const consoleT = { log: (l, m) => console.log(l, m) }
const metricsT = { log: (l, m, meta) => metrics.increment(m) }

logixlysia({
  config: {
    transports: [tee([consoleT, metricsT])],
  },
})
```

### sample —— 概率采样

以 `rate` (0-1) 的概率把 log 转发给 transport。`rate=0` 完全丢弃,`rate=1` 等于直通。`rate` 越界抛 `Error`。

```ts
import logixlysia, { tee, sample } from '@pori15/logixlysia'

logixlysia({
  config: {
    transports: [
      tee([
        sample(0.1, metricsT),  // 10% 进 metrics
        consoleT,                // 100% 进 console
      ]),
    ],
  },
})
```

### filter —— 谓词过滤

仅当 `predicate(level, message, meta)` 返回 truthy 时才转发。最常见:ERROR 才告警。

```ts
import logixlysia, { tee, filter, sample } from '@pori15/logixlysia'

const slackAlerter = { log: async (l, m) => fetch(process.env.SLACK_WEBHOOK!, { ... }) }

logixlysia({
  config: {
    transports: [
      tee([
        filter((lvl) => lvl === 'ERROR', slackAlerter),
        sample(0.1, metricsT),
        consoleT,
      ]),
    ],
  },
})
```

### tap —— 旁路

对每条 log 跑 `fn`,**然后总是**转发给 transport。适合打 metrics / 计数 / 调试 trace。`fn` 抛错会被静默吞(不影响主链路)。

```ts
import logixlysia, { tap, sample } from '@pori15/logixlysia'

let counter = 0

logixlysia({
  config: {
    transports: [
      tap(
        (lvl, msg, meta) => {
          counter++
          if (meta?.durationMs && meta.durationMs > 1000) {
            console.warn('slow request', meta)
          }
        },
        sample(0.01, metricsT),  // 计数 100%,metrics 采样 1%
      ),
    ],
  },
})
```

### batch —— 缓冲

缓冲 log 直到满 `size` 条**或**距首条 `flushMs` 毫秒,触发后作为一条 `INFO` "batch" 发出去,`meta.entries` 是缓冲数组。`size` / `flushMs` ≤ 0 抛 `Error`。

适合打远程服务(每次 HTTP 请求成本高):

```ts
import logixlysia, { batch, filter, tee } from '@pori15/logixlysia'

const httpSink = { log: async (lvl, msg, meta) => {
  await fetch('https://logs.example.com/ingest', {
    method: 'POST',
    body: JSON.stringify({ lvl, msg, meta }),
  })
}}

logixlysia({
  config: {
    transports: [
      tee([
        filter((lvl) => lvl === 'DEBUG', batch(50, 5000, httpSink)),  // DEBUG 批量 5s
        consoleT,
      ]),
    ],
  },
})
```

**注意**:程序退出时未刷的 buffer 会丢。在 `beforeExit` / SIGTERM handler 里**目前没有**自动 flush 机制(等 PR)—— 自己用 `setTimeout` / 长进程 / 接收 SIGTERM 的方式让 batch 自然触发。

### 组合原则

- 每个组合器**只做一件事**,任意堆叠;
- 顺序敏感:`filter` 放在 `tee` 之前比之后便宜(早 fail 早 return);
- 涉及副作用的(metrics / 计数)用 `tap`,**绝不要**用 `filter` 丢日志;
- 远程 / 慢 transport 一定套 `batch`,否则一个请求一条 HTTP 成本压垮服务。
