title: Custom Transports

用自定义 transport 把日志发到外部服务。transport 跟内置的 console / file 日志并行,统一从 emit 管道调用。

## 输出行为

Logixlysia 支持三种输出目标:

1. **Console 日志** —— 内置控制台输出
2. **File 日志** —— 通过 file sink 输出
3. **Transport 日志** —— 自定义外部服务

### 输出控制

- **默认:** console + file(如果设置了 `logFilePath`)+ transports
- **`disableInternalLogger: true`:** 只关 console
- **`disableFileLogging: true`:** 只关 file
- **`useTransportsOnly: true`:** 同时关 console 和 file,只走 transport

## 基本 transport

```ts
import type { Transport } from '@pori15/logixlysia'

const consoleTransport: Transport = {
  log: (level, message, meta) => {
    console.log(`[${level}] ${message}`, meta)
  },
}

app.use(
  logixlysia({
    config: {
      transports: [consoleTransport],
    },
  })
)
```

签名是 `(level: LogLevel, message: string, meta?: Record<string, unknown>) => void | Promise<void>`。异步 transport 返回 promise,同步 transport 返回 `void`。

## 外部服务

### Elasticsearch

```ts
const elasticsearchTransport: Transport = {
  log: async (level, message, meta) => {
    await fetch('http://elasticsearch:9200/logs/_doc', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        level,
        message,
        ...meta,
        timestamp: new Date().toISOString(),
      }),
    })
  },
}
```

### MongoDB

```ts
const mongodbTransport: Transport = {
  log: async (level, message, meta) => {
    await db.collection('logs').insertOne({
      level,
      message,
      ...meta,
      timestamp: new Date(),
    })
  },
}
```

### Slack

```ts
const slackTransport: Transport = {
  log: async (level, message, meta) => {
    if (level !== 'ERROR') return
    const webhook = process.env.SLACK_WEBHOOK_URL
    if (!webhook) return

    await fetch(webhook, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({
        text: `[${level}] ${message}\n\`\`\`${JSON.stringify(meta, null, 2)}\`\`\``,
      }),
    })
  },
}
```

## 多个 transport

```ts
app.use(
  logixlysia({
    config: {
      transports: [elasticsearchTransport, slackTransport],
    },
  })
)
```

数组里的 transport 顺序调用,各自独立 —— Elasticsearch 慢不会阻塞 Slack。

## 只用 transport

```ts
app.use(
  logixlysia({
    config: {
      useTransportsOnly: true,
      transports: [elasticsearchTransport, slackTransport],
    },
  })
)
```

## 错误处理 & 节流

transport 抛出的同步异常和异步 reject 都会被捕获并打印到 `console.error`。为了防止坏掉的 transport 每个请求都刷一屏 stderr,同一 transport 的同一错误在 `transportThrottleMs`(默认 5s)窗口内合并为一条 `console.error`。

```ts
logixlysia({
  config: {
    transportThrottleMs: 10_000, // 10s 窗口
  },
})
```

这是生产环境的安全阀。你仍然应该在 transport 内部自己处理错误,接到自己的监控系统。

## 最佳实践

- **在 transport 内部处理错误** —— logixlysia 捕获了 throw,但只打印到 `console.error`,不会送回你的目标。
- **异步用 `Promise<void>`** —— logixlysia 会 await 异步 transport 的返回值。
- **避免在 `meta` 里写 secret / PII** —— 脱敏会处理 message 和 key 字段,但 transport 拿到的就是管道给的原始数据。
- **生产只接外部聚合器时,设 `useTransportsOnly: true`**
- **按重要性排 transport 顺序** —— 告警放最前,批写放最后

## Transport 接口

```ts
export interface Transport {
  log: (
    level: LogLevel,
    message: string,
    meta?: Record<string, unknown>
  ) => void | Promise<void>
}

export type LogLevel = 'DEBUG' | 'INFO' | 'WARNING' | 'ERROR'
```
