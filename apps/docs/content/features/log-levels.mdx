title: Log Levels
description: Control log verbosity
---

Control the verbosity of log output with Logixlysia's level system. Levels are case-insensitive strings: `DEBUG`, `INFO`, `WARNING`, `ERROR`.

## Available levels

```
DEBUG > INFO > WARNING > ERROR
```

Logixlysia uses **allowlist filtering**, not hierarchy. Setting `logFilter.level: ['ERROR']` outputs only `ERROR`; setting it to `['ERROR', 'WARNING']` outputs both. The order of levels in the array does not matter.

## Configuration

### Single level

```ts
logixlysia({
  config: {
    logFilter: { level: 'ERROR' },
  },
})
```

### Multiple levels

```ts
logixlysia({
  config: {
    logFilter: { level: ['INFO', 'ERROR'] },
  },
})
```

### Root shorthand

`logLevel` at the root of the options object is equivalent to `config.logFilter.level`:

```ts
logixlysia({ logLevel: ['ERROR', 'WARNING'] })
```

Both forms are merged: if you set both, `logLevel` wins (root shorthand takes precedence when set).

### Environment-based

```ts
logixlysia({
  config: {
    logFilter: {
      level: process.env.NODE_ENV === 'production'
        ? ['ERROR', 'WARNING']
        : ['DEBUG', 'INFO', 'WARNING', 'ERROR'],
    },
  },
})
```

## Status-derived level

In addition to explicit `logFilter.level`, every access log gets a level derived from the response status code:

| Status range | Level |
| --- | --- |
| `200`–`399` | `INFO` |
| `400`–`499` | `WARNING` |
| `500`–`599` | `ERROR` |

The status-derived level is filtered through `logFilter.level` (or `logLevel`) just like explicit calls — a 404 will not produce output if `level: ['ERROR']`.

## Pino log levels

Pino has its own level system (`fatal`, `error`, `warn`, `info`, `debug`, `trace`). `config.pino.level` controls Pino's gate and is independent of `logFilter.level`:

```ts
logixlysia({
  config: {
    pino: { level: 'debug' },
  },
})
```

Pino is constructed lazily on first access. Set `config.pino` to a truthy value if you want invalid Pino options to fail at startup.

## Best practices

- **Development:** `['DEBUG', 'INFO', 'WARNING', 'ERROR']` — all four
- **Staging:** `['INFO', 'WARNING', 'ERROR']` — drop DEBUG
- **Production:** `['ERROR', 'WARNING']` — drop INFO and DEBUG
- **Alerting:** `['ERROR']` — alerts only on errors
