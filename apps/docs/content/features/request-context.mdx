---
title: Request context
description: Accumulate request-scoped fields into a single access log line
---

Logixlysia accumulates context during a request and merges it into the automatic access log — similar to evlog wide events, without replacing your existing `logger.info()` API.

## Basic usage

```ts
import { Elysia } from 'elysia'
import logixlysia from '@pori15/logixlysia'

const app = new Elysia()
  .use(logixlysia())
  .get('/checkout', ({ request, store }) => {
    store.logger.mergeContext(request, { userId: 'usr_123' })
    store.logger.mergeContext(request, { cartTotal: 9999 })
    return { ok: true }
  })
```

The final `INFO` access log includes a `context` object with `userId` and `cartTotal` (and renders as a context tree when `showContextTree` is enabled).

## Logger API

`store.logger` exposes nine methods:

| Method | Purpose |
| --- | --- |
| `debug(request, message, context?)` | Log at DEBUG |
| `info(request, message, context?)` | Log at INFO |
| `warn(request, message, context?)` | Log at WARNING |
| `error(request, message, context?)` | Log at ERROR |
| `log(level, request, data, store)` | Explicit level + structured data entry |
| `handleHttpError(request, error, store, options?)` | Process a thrown error and emit a leveled log |
| `getContext(request)` | Read the accumulated per-request context bag |
| `mergeContext(request, partial)` | Merge a partial into the per-request context bag |
| `pino` | Underlying Pino Logger instance |

## Precedence

When you call `logger.info(request, message, { ...explicit })`, keys in the explicit context **override** accumulated values. Non-colliding keys from both sources are kept.

```ts
store.logger.mergeContext(request, { userId: 'usr_123', role: 'guest' })
store.logger.info(request, 'fetched user', { role: 'admin', email: 'a@b.co' })
// Final context: { userId: 'usr_123', role: 'admin', email: 'a@b.co' }
```

## Reading context

```ts
const ctx = store.logger.getContext(request)
// Readonly<Record<string, unknown>>
```

The returned object is a frozen view; mutating it has no effect. Use `mergeContext` to add more fields.

## Request-scoped logger & AsyncLocalStorage

Instead of manually passing the `request` object to `store.logger` methods (e.g. `store.logger.info(request, message)`), enable `AsyncLocalStorage` propagation so a request-scoped `log` is derived on the Elysia handler context:

```ts
logixlysia({
  config: {
    useAsyncLocalStorage: true,
  },
})
```

### 1. Handler context (`log`)

Destructure `log` directly in route handlers:

```ts
app.get('/user/:id', ({ log, params }) => {
  log.mergeContext({ userId: params.id })
  log.info('Fetched user profile')
  return { success: true }
})
```

The `log` handle has no `request` parameter — it is bound to the active request through `AsyncLocalStorage`. The same `log.mergeContext` / `log.info` / `log.warn` / `log.error` / `log.debug` shape as `store.logger`, minus the request.

### 2. Global hook (`useLogger()`)

In nested service layers or helper functions, import `useLogger()` to log or merge context from any depth in the call stack:

```ts
import { useLogger } from '@pori15/logixlysia'

async function findUser(id: string) {
  const log = useLogger()
  log.mergeContext({ action: 'db_query' })
  log.info('Executing database lookup…')

  // Database lookup logic…
  return { id, name: 'John Doe' }
}
```

`useLogger()` returns the same `RequestScopedLogger` shape as the handler `log`. Outside a request (during startup, in a worker, in a cron tick) it returns `undefined`-safe no-ops; calls become inert.

### Caveats

- ALS propagation only works inside a request that flowed through the logixlysia plugin's `.request()` hook. Background work scheduled outside a request lifecycle will get the no-op `log` and emit nothing.
- ALS is opt-in. Default behavior keeps the explicit `store.logger` API only — turn ALS on for new code that wants deep call-stack logging.
