---
title: Request ID
description: 在请求和响应之间生成或透传唯一标识
---

Logixlysia 自动生成或读取唯一请求标识(request ID),挂到请求 context、响应头和日志输出上。

## 基本用法

用 `requestId: true` 开启。默认配置使用 `X-Request-Id` 头和 UUID v4 生成器。

```ts
import { Elysia } from 'elysia'
import { logixlysia } from '@pori15/logixlysia'

const app = new Elysia().use(
  logixlysia({
    config: {
      requestId: true,
    },
  })
)
```

## 生产 preset

`prod` preset 自动开启 `requestId`:

```ts
const app = new Elysia().use(
  logixlysia({
    preset: 'prod', // 自动开启 requestId
  })
)
```

## 自定义配置

需要更细的控制时,传配置对象:

```ts
const app = new Elysia().use(
  logixlysia({
    config: {
      requestId: {
        // 自定义读取 / 写入的 header 名
        header: 'X-Correlation-Id',
        // 自定义 request ID 生成函数
        generator: () => `req-${crypto.randomUUID()}`,
      },
    },
  })
)
```

### 选项

| 选项 | 类型 | 默认 | 描述 |
| --- | --- | --- | --- |
| `enabled` | `boolean` | `true` | 用对象配置时,显式开关 request ID 生成 |
| `header` | `string` | `'X-Request-Id'` | 入口读、出口写的 header 名 |
| `generator` | `() => string` | `crypto.randomUUID` | 返回唯一字符串的生成函数 |

## 工作机制

1. 请求进入时,插件从入站 `Request` 读配置的 header(默认 `X-Request-Id`)。
2. 如果缺失,用 `generator` 生成一个。
3. ID 存到请求作用域 context 包的 `requestId` 字段。
4. 响应阶段(`afterHandle` 钩子)把 ID 写回响应 header。
5. 错误响应同样在响应 header 和错误日志 context 里带上 ID —— 方便失败请求的 trace 关联。

## 日志格式化

在自定义日志格式里用 `{requestId}` 占位符输出 request ID:

```ts
const app = new Elysia().use(
  logixlysia({
    config: {
      requestId: true,
      customLogFormat: '{method} {pathname} - Request ID: {requestId}',
    },
  })
)
```

request ID 没开启或缺失时,token 渲染为空字符串。

## 跨服务追踪

把 request ID 跟 `autoRedact: true` 配对,让 `authorization` 和 `cookie` 头在 access log 里被脱敏,但 request ID 仍能 grep:

```ts
logixlysia({
  config: {
    requestId: true,
    autoRedact: true,
    customLogFormat: '[{requestId}] {method} {pathname} {status} {duration}ms',
  },
})
```

分布式追踪场景,再叠一层 OpenTelemetry(见 [OpenTelemetry](/docs/integrations/otel))。request ID 和 trace ID 是独立的 —— request ID 是你的应用层关联键,trace ID 是 OTel 那一层的。
