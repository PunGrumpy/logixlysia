---
title: WebSocket logging
description: Log WebSocket open, message, and close events
---

Use `createWsHandlerWrapper` to add lifecycle logs for WebSocket routes:

```ts
import { Elysia } from 'elysia'
import { createElogs, createWsHandlerWrapper } from 'createElogs'

const plugin = createElogs({
  config: {
    service: 'chat'
  }
})
// 跟 createElogs 共享同一份 logger / context store,
// 所以 wrap 出来的事件能直接走 access log 管道。
const wrapWs = createWsHandlerWrapper()

const app = new Elysia()
  .use(plugin)
  .ws(
    '/chat',
    wrapWs({
      open(ws) {
        ws.send('connected')
      },
      message(ws, message) {
        ws.send(message)
      },
      close(ws) {
        console.log('bye', ws.id)
      }
    })
  )
```

Each lifecycle event logs with HTTP method `WS`, the route path, duration, and optional `wsId` in context.

## Request context on WebSockets

Accumulate context with the WebSocket instance as the key:

```ts
.ws(
  '/chat',
  wrapWs({
    message(ws, payload) {
      ws.data.store.logger.mergeContext(ws, { lastPayloadType: typeof payload })
    }
  })
)
```

## Disable WebSocket logs

```ts
createElogs({
  config: {
    disableWebSocketLogging: true
  }
})
```

## Why a separate export?

Elysia 2 用 `#private` brand 标记合法 plugin 实例,直接在 plugin 上挂额外字段(像
`plugin.wrapWs`)会破坏这个 brand,导致 `.use()` 报类型错误。`createWsHandlerWrapper`
作为独立函数导出,绕开这个限制,同时保证它和 `createElogs` 跑在同一份 logger 上下文。
