---
title: WebSocket logging
description: Log WebSocket open, message, and close events
---

Use `wrapWs` on the plugin instance to add lifecycle logs for WebSocket routes:

```ts
import { Elysia } from 'elysia'
import logixlysia from 'logixlysia'

const plugin = logixlysia({
  config: {
    service: 'chat'
  }
})

interface ChatWs {
  send(data: unknown): void
}

const app = new Elysia().use(plugin).ws('/chat', {
  ...plugin.wrapWs('/chat', {
    open(ws) {
      ;(ws as unknown as ChatWs).send('connected')
    },
    message(ws, message) {
      ;(ws as unknown as ChatWs).send(message)
    },
    close(ws) {
      console.log('bye', ws.id)
    }
  })
})
```

The hooks type the socket as the plugin's `WebSocketLike`, which does not declare `send`, so the example casts it to a local `ChatWs`; a typed default is a planned library improvement.

A hook may reply by returning a value, a promise or a generator, and Elysia sends a wrapped hook's reply as it sends an unwrapped one's: the value, what the promise resolves to, or each value the generator yields. `wrapWs` passes a generator (what a `function*` or `async function*` returns) through a wrapper of its own so it can log when the generator ends. Any other value, a hand-written iterator included, reaches Elysia as it is.

Each lifecycle event logs with HTTP method `WS`, the route path, the connection's age (shown where an HTTP line shows its duration), status `200`, and optional `wsId` in context. Your `close` hook receives the WebSocket's close `code` and `reason`, and the "WebSocket closed" line logs them too.

A hook that throws or rejects gets an `ERROR` line in place of its usual line. That line carries the error in its `error` field, as an HTTP error line does, and no status, since the client was sent none; the error still reaches Elysia's `onError`. An `open` or `message` hook that returns a generator is logged when the generator finishes, so the connection's age on that line includes the time spent sending, and a throw inside the generator gets the same `ERROR` line. Any other value is logged when the hook returns or its promise settles. A `close` hook is always logged then, whatever it returned, and the connection's context is cleared at that point.

## Request context on WebSockets

Accumulate context with the WebSocket instance as the key:

```ts
.ws('/chat', {
  ...plugin.wrapWs('/chat', {
    message(ws, payload) {
      plugin.store.logger.mergeContext(ws, { lastPayloadType: typeof payload })
    }
  })
})
```

The plugin stores context per connection, so a value merged in `open` is still there on later message and close lines.

## Disable WebSocket logs

```ts
logixlysia({
  config: {
    disableWebSocketLogging: true
  }
})
```
