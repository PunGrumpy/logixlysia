---
title: Presets
description: 现成的 dev、prod、json 日志默认值
---

用 `preset` 一行设好环境默认。显式 `config` 字段永远覆盖 preset。

```ts
import { Elysia } from 'elysia'
import logixlysia from '@pori15/logixlysia'

const app = new Elysia().use(
  logixlysia({
    preset: 'prod',
    config: {
      service: 'api',
      logFilePath: './logs/app.log',
    },
  })
)
```

## 可用 preset

| Preset | 启动 banner | 美化输出 | context 树 | `autoRedact` | `requestId` |
| --- | --- | --- | --- | --- | --- |
| `dev` | 是(banner) | 是 | 是 | 否 | 否 |
| `prod` | 否 | 否 | 否 | 是 | 是 |
| `json` | 否 | 否 | 否 | 否 | 否 |

`json` 是日志聚合器(Datadog、Loki、Elasticsearch)的最小配置 —— 关掉所有装饰性输出,JSON 是唯一 payload。下游需要解析行分隔 JSON、又不需要人类可读格式时用它。

## 覆盖示例

```ts
logixlysia({
  preset: 'prod',
  config: {
    autoRedact: false,
    showStartupMessage: true,
  },
})
```

## 程序化解析

如果想先看解析后的 options 再往下传,用 `resolveOptions`:

```ts
import { resolveOptions } from '@pori15/logixlysia'

const options = resolveOptions({ preset: 'dev', config: { service: 'api' } })
// options.config.service === 'api'
// options.config.showStartupMessage === true (来自 dev preset)
```

`resolveOptions` 就是插件内部用的同一个 merge 函数,行为跟直接传给 `logixlysia()` 完全一致。
