Logixlysia integrates with [Pino](https://github.com/pinojs/pino) as its underlying logging engine. Pino is constructed lazily on first access — invalid Pino options only fail when you actually log.

## Why Pino?

- **High performance** — one of the fastest Node.js loggers
- **Structured logging** — JSON-first
- **Battle-tested** — production-grade
- **Flexible** — extensive options and transport support

## Basic usage

### In Elysia routes

Access Pino through the store in route handlers:

```ts
app.get('/users/:id', ({ store, params }) => {
  const { pino } = store

  pino.info({
    userId: params.id,
    action: 'view_profile',
  }, 'User profile accessed')

  return { user: 'data' }
})
```

Or via the request-scoped `log` (when `useAsyncLocalStorage: true`):

```ts
app.get('/users/:id', ({ log, params }) => {
  log.pino.info({ userId: params.id, action: 'view_profile' }, 'profile accessed')
  return { user: 'data' }
})
```

### Outside Elysia routes (standalone)

Use Pino in services, background jobs, or any code outside of HTTP request context:

```ts
// logger.ts
import logixlysia from '@pori15/logixlysia'

export const logixlysiaIns = logixlysia({
  config: {
    logFilePath: './logs/app.log',
    pino: {
      level: 'info',
      base: {
        service: 'my-api',
        version: '1.0.0',
      },
    },
  },
})

// Export Pino instance for standalone use
export const logger = logixlysiaIns.store.pino
```

```ts
// services/order.service.ts
import { logger } from '../logger'

export class OrderService {
  async processOrder(orderId: string) {
    logger.info({ orderId }, 'Processing order')

    try {
      // ... business logic
      logger.info({ orderId }, 'Order processed successfully')
    } catch (error) {
      logger.error({ orderId, error }, 'Order processing failed')
      throw error
    }
  }
}
```

```ts
// index.ts
import { Elysia } from 'elysia'
import { logixlysiaIns } from './logger'
import { OrderService } from './services/order.service'

const orderService = new OrderService()

new Elysia()
  .use(logixlysiaIns)
  .post('/orders/:id/process', async ({ params }) => {
    await orderService.processOrder(params.id)
    return { success: true }
  })
  .listen(3000)
```

**Note:** When using Pino outside of routes, you will not have access to HTTP context (method, pathname, IP, etc.). For HTTP request logging, use `store.logger` inside route handlers.

## Configuration

### Log level

```ts
logixlysia({
  config: {
    pino: {
      level: 'debug', // 'fatal' | 'error' | 'warn' | 'info' | 'debug' | 'trace'
    },
  },
})
```

### Pretty printing

```ts
logixlysia({
  config: {
    pino: {
      prettyPrint: true,
    },
  },
})
```

Or with custom options:

```ts
logixlysia({
  config: {
    pino: {
      prettyPrint: {
        colorize: true,
        translateTime: 'HH:MM:ss Z',
        ignore: 'pid,hostname',
      },
    },
  },
})
```

`prettyPrint` is a passthrough to [pino-pretty](https://github.com/pinojs/pino-pretty). Install `pino-pretty` as a peer dep if you use it.

### Redacting sensitive data

Pino's own `redact` is independent of Logixlysia's `autoRedact` — both can run side by side:

```ts
logixlysia({
  config: {
    autoRedact: true,                 // Logixlysia: rewrites meta + headers
    pino: { redact: ['password'] },   // Pino: scrubs the JSON output
  },
})
```

```ts
// Or with paths and removal:
pino: {
  redact: {
    paths: ['user.password', 'req.headers.authorization'],
    remove: true,
  },
},
```

### Base fields

```ts
logixlysia({
  config: {
    pino: {
      base: {
        service: 'my-api',
        version: '1.0.0',
        environment: process.env.NODE_ENV,
      },
    },
  },
})
```

### Pino transports

Pino has its own transport system for advanced logging destinations. Configure Pino transports with the `transport` option:

```ts
logixlysia({
  config: {
    pino: {
      transport: {
        target: 'pino/file',
        options: { destination: './logs/pino-example.log' },
      },
    },
  },
})
```

**Important:** Pino transports and Logixlysia transports are independent:

- **Pino transports** (`pino.transport`) — affect logs written through `store.pino.info()`, `store.pino.error()`, etc.
- **Logixlysia transports** (`config.transports`) — affect the HTTP access log pipeline

```ts
logixlysia({
  config: {
    // Pino transport — only for store.pino.* logs
    pino: {
      transport: { target: 'pino/file', options: { destination: './logs/pino.log' } },
    },
    // Logixlysia transport — only for HTTP access logs
    transports: [customTransport],
  },
})

app.get('/example', ({ store }) => {
  store.pino.info({ feature: 'pino' }, 'pino log example')
  // → goes to pino/file transport
  // The HTTP access log goes to the Logixlysia transport
})
```

## Advanced usage

### Structured logging

```ts
app.get('/users/:id', ({ store, params }) => {
  const { pino } = store

  pino.info({
    userId: params.id,
    action: 'view_profile',
    timestamp: Date.now(),
  }, 'User profile viewed')

  return user
})
```

### Child loggers

Create child loggers with bound context:

```ts
app.get('/api/orders/:id', ({ store, params }) => {
  const { pino } = store

  const orderLogger = pino.child({
    orderId: params.id,
    module: 'order-service',
  })

  orderLogger.info('Fetching order details')
  orderLogger.debug({ query: 'SELECT * FROM orders WHERE id = ?' })

  return order
})
```

### Error logging

```ts
app.get('/api/risky', ({ store }) => {
  const { pino } = store

  try {
    performRiskyOperation()
  } catch (error) {
    pino.error({ err: error, operation: 'risky_operation' }, 'Operation failed')
    throw error
  }
})
```

## Lazy initialization

Pino is constructed lazily on first access. This means:

```ts
const plugin = logixlysia({
  config: {
    pino: { level: 'invalid-level' as any },
  },
})

// ... plugin constructed, no error yet
// ... first call to plugin.store.pino.info() throws
```

To force eager initialization (so bad Pino options fail at startup), set `config.pino` to any truthy value. The Pino instance is created when the plugin is built.

## Environment-based configuration

```ts
const isDev = process.env.NODE_ENV === 'development'

logixlysia({
  config: {
    pino: {
      level: isDev ? 'debug' : 'info',
      prettyPrint: isDev,
      redact: isDev ? [] : ['password', 'token', 'apiKey'],
      base: {
        service: 'my-api',
        environment: process.env.NODE_ENV,
      },
    },
  },
})
```

## Best practices

1. **Use structured logging** — pass objects instead of string interpolation
   ```ts
   // ✅
   pino.info({ userId: 123, action: 'login' }, 'User logged in')
   // ❌
   pino.info(`User ${userId} logged in`)
   ```

2. **Create child loggers** for scoped context

3. **Log performance metrics** — track important operations
   ```ts
   pino.info({ duration: 150, operation: 'db_query' }, 'Query completed')
   ```

4. **Redact sensitive data** — use both `autoRedact` (Logixlysia) and `pino.redact` (Pino)

5. **Use the right level:**
   - `fatal` — application is about to crash
   - `error` — error that needs attention
   - `warn` — warning, application continues
   - `info` — general information (default)
   - `debug` — detailed debugging
   - `trace` — very detailed debugging

6. **Export Pino for standalone use** in services, jobs, and utilities
   ```ts
   export const logger = logixlysiaIns.store.pino
   ```
