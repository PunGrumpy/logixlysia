---
title: Elysia 2 support
description: How Logixlysia maps onto the Elysia 2 open beta, and what changes when you upgrade
---

[Elysia 2 "DayDream"](https://elysiajs.com/blog/elysia-20) is a full rewrite of the framework. It renames every
lifecycle hook, changes the `Elysia` type parameters, and moves WebSocket support behind an opt-in plugin.
Logixlysia cannot support both major versions from one build, so the two lines are published separately.

## Compatibility

| Elysia      | Logixlysia    | npm tag  | Install                                |
| ----------- | ------------- | -------- | -------------------------------------- |
| `1.4.x`     | `6.x`         | `latest` | `bun add logixlysia`                   |
| `>= 2.0.0-beta.2` | `7.x-next` | `next`   | `bun add logixlysia@next elysia@next`  |

The `next` line follows the Elysia 2 beta and may take further breaking changes until Elysia 2 is stable.

## What changed in your app

Elysia 2 dropped the `on` prefix from lifecycle methods, and there are no aliases left behind. If you register
hooks around Logixlysia, rename them:

| Elysia 1.4         | Elysia 2       |
| ------------------ | -------------- |
| `.onStart()`       | `.setup()`     |
| `.onStop()`        | `.cleanup()`   |
| `.onRequest()`     | `.request()`   |
| `.onTransform()`   | `.transform()` |
| `.onBeforeHandle()`| `.beforeHandle()` |
| `.onAfterHandle()` | `.afterHandle()`  |
| `.onAfterResponse()` | `.afterResponse()` |
| `.onMapResponse()` | `.mapResponse()`  |
| `.onError()`       | `.error()`     |
| `.as('scoped')`    | `.as('plugin')` |

`resolve` was removed and `derive` now runs during `beforeHandle`. Logixlysia derives `ctx.log` there, so it is
available in `beforeHandle`, the route handler and `afterHandle` — but no longer in `parse` or `transform`. Use
`store.logger` (which is set up in the `request` hook) if you need to log that early.

WebSocket routes need the opt-in provider before `plugin.wrapWs` has anything to wrap:

```ts
import { Elysia } from 'elysia'
import { websocket } from 'elysia/websocket'
import logixlysia from 'logixlysia'

const logging = logixlysia()

const app = new Elysia()
  .use(websocket())
  .use(logging)
  .ws('/ws', {
    ...logging.wrapWs('/ws', {
      message(ws, message) {
        ws.send(message)
      }
    })
  })
```

`trace` and automatic `HEAD` routes moved the same way, to `elysia/trace` and `elysia/auto-head`.

## What did not change

The Logixlysia API itself is unchanged: `logixlysia(options)`, the `preset`/`config` shape, `store.logger`,
`ctx.log`, `useLogger()`, `createLogger()`, `plugin.wrapWs`, and the `logixlysia/otel` and `logixlysia/ai`
subpaths all behave exactly as they do on the 6.x line.

## Error logging under Elysia 2

Two framework behaviour changes show up in your logs:

- Errors are reported as [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) problem documents by default.
- When `NODE_ENV=production`, an unhandled error's `message` is no longer sent to the client, and a returned
  `Error` is serialized without its `cause`.

Neither affects what Logixlysia writes — the full error is still logged server-side, subject to your
`logErrorPayload` and `autoRedact` settings.
