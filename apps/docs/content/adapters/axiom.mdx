title: Axiom
description: Ship logs to an Axiom dataset via the ingest API

Send logs to [Axiom](https://axiom.co). Axiom indexes every field of an event without a schema, so the nested structure Logixlysia sends — `request.method`, `context.requestId`, your custom context — is queryable as-is with APL.

## Setup

1. Create a dataset in the [Axiom console](https://app.axiom.co).
2. Generate an API token with **ingest** permission for that dataset.
3. Set the environment variables:

```bash
AXIOM_API_KEY=xaat-your-token
AXIOM_DATASET=your-dataset
```

4. Wire the transport:

```ts
import { Elysia } from 'elysia'
import logixlysia from 'logixlysia'
import { createAxiomTransport } from 'logixlysia/axiom'

const app = new Elysia()
  .use(
    logixlysia({
      config: {
        transports: [createAxiomTransport()]
      }
    })
  )
  .get('/', () => 'ok')
  .listen(3000)
```

5. Trigger a request and query the dataset in Axiom.

## Environment Variables

| Variable | Required | Description |
| --- | --- | --- |
| `AXIOM_API_KEY` | Yes | API token with ingest permission (`xaat-…`) |
| `AXIOM_DATASET` | Yes | Target dataset name |
| `AXIOM_ORG_ID` | For personal access tokens | Organization ID |
| `AXIOM_URL` | No | Base URL of the default ingest endpoint (default `https://api.axiom.co`) |
| `AXIOM_EDGE` | No | Edge domain to ingest through, such as `eu-central-1.aws.edge.axiom.co` |
| `AXIOM_EDGE_URL` | No | Full URL of an edge endpoint or of a proxy in front of one |

## Options

Options passed to `createAxiomTransport()` override environment variables:

```ts
const axiom = createAxiomTransport({
  dataset: 'production-logs',
  timeout: 10_000
})
```

| Option | Type | Default | Description |
| --- | --- | --- | --- |
| `apiKey` | `string` | `AXIOM_API_KEY` | API token with ingest permission |
| `dataset` | `string` | `AXIOM_DATASET` | Target dataset name |
| `orgId` | `string` | `AXIOM_ORG_ID` | Required when using a personal access token |
| `baseUrl` | `string` | `https://api.axiom.co` | Base URL of the default ingest endpoint |
| `edge` | `string` | `AXIOM_EDGE` | Edge domain to ingest through, without a scheme or a path; a port is allowed |
| `edgeUrl` | `string` | `AXIOM_EDGE_URL` | Full URL of an edge endpoint or of a proxy in front of one |

Plus the shared options in the [overview table](/docs/adapters/overview#shared-behavior).

## Regions

Axiom ingests through regional [edge deployments](https://axiom.co/docs/reference/edge-deployments). By default the transport posts to `https://api.axiom.co/v1/datasets/{dataset}/ingest`, which Axiom's API reference describes as a legacy endpoint that ingests into US East 1. For a dataset in another deployment, set the edge domain Axiom lists for it:

```bash
AXIOM_EDGE=eu-central-1.aws.edge.axiom.co
```

The transport then posts to `https://{edge}/v1/ingest/{dataset}`. Axiom's reference says that endpoint supports API tokens only, not personal access tokens.

`edgeUrl` takes a full URL instead, without a user name or a password, for a proxy in front of an edge endpoint. Trailing slashes are removed from its path. If nothing is left, the path becomes `/v1/ingest/{dataset}`; otherwise it is kept.

`edgeUrl` wins over `edge`, and `edge` wins over `baseUrl`. If you pass any of the three as an option, `AXIOM_EDGE_URL`, `AXIOM_EDGE` and `AXIOM_URL` are not read.

## Payload

Each log becomes one event in the body of the ingest request:

```json
{
  "_time": "2026-08-22T12:00:00.000Z",
  "level": "INFO",
  "message": "",
  "request": { "method": "GET", "url": "http://localhost:3000/users" },
  "status": 200,
  "durationMs": 12.4,
  "context": { "requestId": "0d5e…" }
}
```

Query it in Axiom with APL, e.g. `['your-dataset'] | where level == "ERROR" and durationMs > 1000`.

## Troubleshooting

- **`401`** — the token is invalid or expired; generate a new one in Axiom settings.
- **`403` with a personal access token** — set `AXIOM_ORG_ID` (personal tokens are not scoped to an organization).
- **Dataset in another edge deployment** — see [Regions](#regions).
- **Nothing arrives** — logs flush in batches (2 s by default); check that the process lived long enough, or call `flush()` before exit.
