## LogixlysiaConfig

### `LogixlysiaConfig`

新版(上游 main)配置 — 所有 createLogPlugin 行为参数集中在 ``config`` 字段下。
同时保留 root-level 字段(legacy + 旧测试)以便向后兼容。

| Field | Type | Optional | Description |
| --- | --- | --- | --- |
| `autoRedact` | `boolean` | ✓ | 自动 redact 敏感信息(headers, body, query string) |
| `contextDepth` | `number` | ✓ | 上下文树展开深度(默认 1) |
| `customLogFormat` | `string` | ✓ | 自定义日志格式模板,支持 token:``{now}`` ``{level}`` ``{duration}`` ``{method}`` ``{pathname}`` ``{status}`` ``{message}`` ``{ip}`` ``{context}`` ``{query}`` ``{statusText}`` ``{requestId}`` ``{service}`` ``{speed}`` 等 |
| `disableFileLogging` | `boolean` | ✓ | 禁用文件日志(即使有 logFilePath) |
| `disableInternalLogger` | `boolean` | ✓ | 禁用内置控制台 logger |
| `disableWebSocketLogging` | `boolean` | ✓ | 禁用 WebSocket 日志 |
| `ip` | `boolean` | ✓ | 在日志中显示 IP(x-forwarded-for / x-real-ip) |
| `logDirMode` | `number` | ✓ | 目录模式(默认 0o700) |
| `logErrorPayload` | `boolean` | ✓ | 把错误对象的 payload(可能是用户输入)写入 meta,默认 false(防泄露) |
| `logFileMode` | `number` | ✓ | 文件模式(默认 0o600) |
| `logFilePath` | `string` | ✓ | 日志文件路径 |
| `logFilter` | `LogFilter` | ✓ | 日志级别过滤 |
| `logQueryParams` | `boolean` | ✓ | 在 pathname 中包含 query string |
| `logRotation` | `LogRotationConfig` | ✓ | 日志轮转 |
| `pino` | `PinoConfig` | ✓ | Pino 配置 |
| `redactKeys` | `string[]` | ✓ | 自定义 redact key 列表(合并到默认敏感 key) |
| `requestId` | `boolean | RequestIdConfig` | ✓ | request-id 跟踪 |
| `service` | `string` | ✓ | 服务名(显示在日志中) |
| `showContextTree` | `boolean` | ✓ | 显示上下文树(默认 true) |
| `showIp` | `boolean` | ✓ | 显示 IP(等价于 ip) |
| `showStartupMessage` | `boolean` | ✓ | 是否显示启动消息 |
| `slowThreshold` | `number` | ✓ | 慢请求阈值(ms),超过显示慢请求标记 |
| `startupMessageFormat` | `"simple" | "banner"` | ✓ | 启动消息格式 |
| `timestamp` | `string | object` | ✓ | 时间戳格式或 { format } |
| `transports` | `Transport[]` | ✓ | 透传 transport 列表(emit 用;``transports`` 也可以在 root,但 emit 只看 config) |
| `transportThrottleMs` | `number` | ✓ | Transport 错误节流窗口(ms) |
| `useAsyncLocalStorage` | `boolean` | ✓ | 启用 AsyncLocalStorage,让 ``useLogger()`` 在深调用栈拿得到 logger。  **实现细节**:在 Elysia 2 的 ``.request()`` 钩子内用 ``loggerStorage.enterWith(...)`` 设置 scope。这会**透传**到后续的路由 handler / ``.afterHandle()``(只要 Elysia 自己在它们之间不再额外 ``als.run()``)。  **限制**: - Elysia 2 升级后如果在内部多次 ``als.run()``,此机制会失效,``useLogger()`` 退回   NOOP_LOGGER,日志被吞。 - ``enterWith`` 不影响"已在运行的 async 树",只影响"从此处之后"新发起的 async。  **推荐**:深调用栈场景优先用 ``({ log })`` derive(Elysia 自己的 context 机制, 不依赖 ALS);``useLogger()`` 仅在"想拿 logger 但不想改签名"的便利场景使用。 |
| `useColors` | `boolean` | ✓ | 启用彩色输出(默认 true 仅 TTY) |
| `useTransportsOnly` | `boolean` | ✓ | 只使用 transports,禁用控制台 + 文件 |
| `verySlowThreshold` | `number` | ✓ | 极慢请求阈值(ms),超过显示更严重标记 |

## CreateLogPluginOptions

### `CreateLogPluginOptions`

Logixlysia 插件配置

新版推荐:``{ config: {...}, preset?: 'dev' | 'prod' | 'json' }``
同时兼容 root-level 字段(legacy tests)

| Field | Type | Optional | Description |
| --- | --- | --- | --- |
| `config` | `LogixlysiaConfig` | ✓ | 新版配置块 |
| `error` | `ErrorConfig` | ✓ | 错误处理配置 |
| `errors` | `LogixlysiaErrorClasses` | ✓ | 用户自定义 HTTPError 类 |
| `file` | `false | FileConfig` | ✓ | 文件日志配置(legacy) |
| `format` | `FormatConfig` | ✓ | 日志格式配置(legacy) |
| `logLevel` | `LogLevel[]` | ✓ | 日志级别过滤 (root-level 别名,等价于 ``config.logFilter.level``) |
| `pino` | `LoggerOptions` | ✓ | Pino Logger 原生配置透传(legacy) |
| `preset` | `"dev" | "prod" | "json" | string & object` | ✓ | 预设,应用一组默认 config 值。 内置:``"dev"`` / ``"prod"`` / ``"json"``(IDE 自动补全)。 任意字符串都行 —— 通过 ``registerPreset(name, defaults)`` 加自己的。 |
| `startup` | `StartupConfig` | ✓ | 启动消息配置(legacy) |
| `transports` | `TransportsConfig | Transport[]` | ✓ | 自定义传输(legacy) |
