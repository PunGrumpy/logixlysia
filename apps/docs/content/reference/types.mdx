### `Logixlysia`

插件返回类型 —— ``ReturnType<typeof logixlysia>``,Elysia 自己推断。
不手写 ``Elysia<...>`` 泛型,避免与 elysia 模块的 ``#private`` brand 冲突。

必须在 ``logixlysia`` 函数声明**之后**导出 (因为下方 ``declare const logixlysia``
才是它的类型来源)。

**bunup 配套要求**:``bunup.config.ts`` 的 ``dts`` 必须开 ``inferTypes: true``,
否则 ``@bunup/dts`` 把函数体当 JS 走 AST,返回类型退化成 ``unknown``。

**为什么返回类型是 ``AnyElysia`` 而不是精确泛型**:开了 ``inferTypes: true`` 之后
真实类型是 ``Elysia<"", "local", {...}>``;它的 ``#private`` 跟 ``AnyElysia`` 的
``#private`` 被 TS 算成不同类,``.use()`` 会拒。在函数签名层加
``(rawOptions?: LogixlysiaOptions) => AnyElysia`` 把出口拓宽到 ``AnyElysia``,
函数体保持单链、零 ``as`` 零 ``any`` 零 ``@ts-expect-error``。

```ts
type Logixlysia = ReturnType<typeof logixlysia>;
```

## Classes

### `HttpError`

Minimal HTTP-aware Error used by logixlysia for non-Elysia call sites
(re-export pipeline, redact tests, integration helpers). Independent of
Elysia 2's ``HTTPError`` (note the capitalisation) — that one lives in
``elysia`` and is the type the framework actually responds with.

```ts
class HttpError {
  cause?: unknown;
  message: string;
  name: string;
  stack?: string;
  status: number;
  stackTraceLimit: number;
  captureStackTrace(targetObject: object, constructorOpt: Function): void;
  isError(value: unknown): undefined value;
  prepareStackTrace(err: Error, stackTraces: CallSite[]): any;
}
```
