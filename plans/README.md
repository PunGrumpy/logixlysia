### Audited but not planned (ready on request)

Verified findings that did not make the default selection. Each is S effort unless noted; evidence is in the plan-style references below.

- **`wrapWs` drops the close code/reason and is not exception-safe** — `src/websocket/wrap-ws.ts:73–80` forwards only `ws` to `hooks.close`, while Elysia calls `close(ws, code, reason)`; user hooks run before cleanup with no `try/finally`, so a throwing hook leaks the connection's context bag and skips the "closed" line; `payloadType: typeof message` cannot distinguish binary frames. - **A failing gzip aborts retention cleanup and double-reports** — `src/output/rotation-manager.ts:80–89` reports then rethrows; `performRotation` (`:173–189`) awaits it unguarded so `maxFiles` cleanup is skipped; `file-sink.ts:163–175` reports the same error again. ### Direction (options for the maintainer, grounded in this repo vs. evlog)

Not ranked against bugs. Each would become a design/spike plan, not a build-everything plan.

1. **Route include/exclude for the access log + a tail-sampling predicate.** `LogFilter` has only `level` (`types/config.ts:32–38`); the glob compiler and matcher already exist and run per request (`sampling/glob.ts`, `sampling/index.ts`), so `logFilter.ignorePaths`/`include` is near-zero new machinery. `TailSamplingConfig` is a closed `{durationMs, paths, status}` struct; `enrichers` already accept arbitrary functions, so a `keep?: (outcome) => boolean` escape hatch is the missing symmetry. evlog: `include`/`exclude` globs and `keep` in `shared/middleware.ts`. Trade-off: a third "what gets logged" concept next to `logFilter.level` and `sampling`; exclusion vs. sampling precedence must be documented.
2. **A public transport-middleware kit.** `withRedaction` (`desertant.ts`) and `createHttpTransport`/`createBatchQueue`/`postWithRetry` (`adapters/shared.ts`, used by all nine adapters) are the same "wrap a transport" pattern, unnamed and unexported. A `logixlysia/transports` subpath exposing them lets third parties write adapter #10 without a PR here. evlog: `pipeline.ts` (`createDrainPipeline`). Trade-off: freezes `BatchTransportOptions` and flatten semantics as public contract; may be over-engineering if nine first-party adapters cover demand. Spike, not build. Sequence after 025/026.
3. **Make the logger observable to itself.** Every loss path is silent: head-sampling drops and the per-request buffer cap (`sampling/index.ts: 145–170`), desertant queue-full drops (own `onError` only), adapter batches that exhaust retries. An `onDropped({ reason, count })` sibling to `onError`, batched off the hot path, is the cheapest honest answer to "are we dropping logs?". evlog: `onDropped`, `diagnostics.ts`. Trade-off: callback first is reversible; a `diagnostics_channel` design is not.
4. **First-party test transport + contributor `create-adapter` skill.** Capture transports are hand-rolled in ~8 test files (`__tests__/sampling/plugin.test.ts:13`, `plugin/logixlysia.test.ts:7`, …) and users have no documented way to assert on logs. Nine templated adapter files with no template or checklist (bunup entry, `exports`, test, docs page, `meta.ts`, changeset) is how `HttpError` shipped unexported. evlog: `adapters/memory.ts`, `.agents/skills/create-adapter`. Trade-off: a public `logixlysia/testing` subpath is a permanent API for something mostly internal; a private `_helpers/transport.ts` may be the honest scope.

evlog features judged **not worth adopting** for an Elysia plugin: audit logging with hash chains, client/browser logging, the CLI and observability score, error catalogs (`HttpError.code`/`link` already cover the benefit), manual wide-event `emit()` (auto-emission is the documented differentiator), an `fs` adapter (file logging with rotation is core), mutation testing in CI (the API snapshot in 024 is higher leverage per hour), and a docker-compose e2e sandbox (adapters are fetch-stubbed only; revisit if a wire-format bug ships).

### Findings considered and rejected

Recorded so nobody re-audits these:

- **Adapter duplication**: all nine adapters route through `createHttpTransport` (or `otlp-core.ts` which does); each file is genuinely vendor-specific body shaping. Well-factored; nothing to consolidate.
- **Four deep-walk implementations** (`redact.ts`, `desertant.ts`, `shared.ts flattenInto`, `create-logger.ts` tree walker): different semantics on purpose (in-place with cycle guard vs. async rebuild with path-scoped `seen` vs. depth-3 flatten vs. display). A shared walker would need four behaviour flags; more complexity than the ~60 lines saved.
- **`exports` lacks a `require` condition** (attw `CJSResolvesToESM`, node10 `NoResolution`): engines `node >= 24`, peer is Elysia; no consumer is on `require()`/node10. Not worth a CJS build.
- **`chalk` → `util.styleText`**: would drop a dependency, but the color path has zero tests today; a blind rewrite of the default output. Revisit after color tests exist.
- **`bun audit` advisories** (37): all reachable only via `apps/docs` (blume/astro), `packages/bench` (evlog/express) and `apps/elysia` (`@elysiajs/swagger`); zero paths through `workspace:logixlysia`. The published package's deps (`chalk`, `pino`, `pino-pretty`) are clean.
- **`typescript` pinned `6.0.3` at root vs `^6.0.3` in leaves**: cosmetic; the consumer-facing floor is the proven peer `>=5.0`.
- **`typecheck` dependsOn `^build`**: correct — `apps/*` import the package through `exports` → `dist/`.
- **`mock.module` leakage in `__tests__/otel/otel-mock.test.ts`**: no new evidence; `otel.test.ts` already documents and tolerates it.
- **`.state('pino', …)` exposure**: documented public API; free until first access because the pino Proxy is lazy.
- **`Logger` vs `RequestScopedLogger` two shapes**: intentional. Minor gap: `TFields` typing applies only to the derived `log`, not `store.logger` — fold into whatever next touches `types/logger.ts`.
- **`beforeHandle` short-circuits losing the access log**: verified NOT a bug — Elysia 1.4 still runs `afterHandle` when `beforeHandle` returns.
- **`beforeTime ?? BigInt(0)` producing a huge duration**: `elapsedMs` treats `0n` as a sentinel and returns `0`; the only path that hits it is fixed by plan 027.
- **`desertant.ts` "poisoned promise tail"**: verified NOT a bug — the task never rejects (all failure paths are caught inside `log`), so a failing record cannot block later records.
- **`desertant.ts` shared sub-object marked `[Circular]`**: NOT a bug — the `seen` set is copied per branch, so a non-cyclic shared reference is redacted twice, not flagged.
