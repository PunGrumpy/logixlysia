With `logErrorPayload: true`, a failed validation is now logged with the `Validation failed (…)` summary as its message, the same as with the option off. Before, on Elysia 1.4, the message was Elysia's own validation message, which by default is a JSON text that includes the value that failed (the request body for a `body` validation, but also the value of a failed `query`, `headers`, `params`, `cookie` or `response` validation), or a schema's custom `error` text, where `autoRedact` cannot mask a value by its key. The submitted value is now in `error.found` and the failures in `error.errors`, each with only its `path` and `message`, on the structured record (the JSON console line and what transports receive). With `autoRedact` on, keys such as `password` inside `found` are masked and every failure's `message` is replaced by `[REDACTED]`, because a validator's message can quote what was submitted; turn `autoRedact` off to read the messages. A failure's `path` and the summary message are logged on both settings and are not masked by key. An application error that only carries `code: 'VALIDATION'`, with no validation data, keeps its own message, `code` and `status`. If you read the JSON text out of the message, read these fields instead. `error.code` and `error.status` no longer appear on a validation error's object; for a request the plugin logs, the record's own `status` still does.
